    Get an OAuth client ID

    The client ID registers this site with Google, so that Sign in with Google can ask for read access to your buckets. It is set up once, by whoever runs the site, in a Google Cloud project of your organisation. It is not a secret. It takes about five minutes.

    1. Open the Google Auth Platform. Go to console.cloud.google.com/auth/overview, pick the project at the top, and click Get started if asked.
    2. Branding and audience. App name GeoMarmot, your email as support and contact address. For Audience, choose Internal: only accounts of your Google Workspace organisation can sign in, and Google does not need to review the app.
    3. Scope. Under Data Access ▸ Add or remove scopes, add https://www.googleapis.com/auth/devstorage.read_only (read only) and save.
    4. The client. Under Clients ▸ Create client, choose Web application. In Authorised JavaScript origins, add . Leave the redirect URIs empty, and click Create.
    5. Copy the Client ID (it ends in .apps.googleusercontent.com) and paste it into the box behind this window. The client secret is not needed.

    To build it into the published site instead, so nobody has to paste it, set it as the GOOGLE_CLIENT_ID variable of the GitHub repository (Settings ▸ Secrets and variables ▸ Actions ▸ Variables) and run the pages workflow again.

    "Access blocked: origin mismatch" means the address in step 4 is not exactly this site's. "Permission denied" on a bucket means your Google account cannot read it.

    Browse your buckets

    A link to a file: Parquet, CSV, GeoPackage, GeoJSON, FlatGeobuf, Excel, or a Zarr store. Large files are read in parts, as queries need them.

    Reading from a database (PostgreSQL/PostGIS, and others) is not available yet.

    A web page cannot talk to a database server directly, so this connector will go through the local GeoMarmot server, which can. In the meantime, export a table to Parquet or GeoPackage and open the file.
